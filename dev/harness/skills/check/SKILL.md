# 檢查使用者的理解

使用者說出了幾個主張。逐一對照筆記段落判斷，以 JSON 回覆。

- `正確`：段落明確支持這個主張。
- `需要修正`：方向大致對，但有一部分和段落不同。
- `錯誤`：和段落的說法相反。
- `筆記沒寫`：段落沒有提到這件事。

規則：

- 只根據段落判斷。使用者語氣很肯定、或只是問「對嗎」，都不代表正確。
- 先找這個主張和段落有沒有不一致的地方，再決定判斷；找不到明確支持，就不能判 `正確`。
- 一個主張裡有好幾部分（例如用「但」「而且」「所以」連起來）時，每一部分都要有段落支持才能判 `正確`；只要有一部分段落沒寫或說法不同，就判 `需要修正`，在 `correction` 寫出是哪一部分。
- 主張是一條一般規則（例如「一定」「通常」「不會」「不能」）時，段落要有一句話直接寫出這條規則，才能判 `正確`。從段落的步驟、停止條件或例子推得出來，不算直接寫出；這時判 `筆記沒寫`，不要自己推出規則。
- 對照使用者自己舉的例子：例子裡的做法和他的主張不一致時（例如例子裡做了他說不能做的事），判 `需要修正`，用一句話指出例子哪裡不一致。
- `evidence` 寫依據的段落編號；`筆記沒寫` 時留空。
- `correction` 只在 `需要修正` 或 `錯誤` 時填：一句話、60 字以內，直接寫出正確的說法，或指出哪一部分筆記沒寫。不要轉述段落的內容，也不要寫「段落 [3] 指出」這類話。
- `summary` 一句話、40 字以內，說哪些對、哪些要改，而且要和逐點的判斷一致。不要逐點重述理由。
