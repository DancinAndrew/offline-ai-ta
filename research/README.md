# 研究規範

研究「別人怎麼做 AI 助教」的規則。主工作階段和平行的研究工作階段都照這份做。整體目標見 [docs/plan.md](../docs/plan.md)。

目標情境：一個離線的課程複習 AI 助教，跑在本機的 qwen3.5:9b（Apple M5、32 GB），用期中範圍的課程筆記開發與驗證。每個發現都要回答一件事：**它適不適用於 9B、本地、離線的情境**。

## 1. 研究主題

| # | 主題 | 要回答的問題 | 優先 |
|---|---|---|---|
| T1 | 案例 | 別人做的課程 AI 助教長什麼樣？功能、架構、成效如何？特別找「考試型複習」和「離線／本地模型」的案例。已知起點：哈佛 CS50 的 AI 助教、喬治亞理工的 Jill Watson（細節待查證） | 高 |
| T2 | 知識與出處 | 怎麼讓 9B 模型根據講義回答，並附上正確出處？投影片 PDF 和中文筆記怎麼切段？課程筆記的 media-note 格式（H3 問題小節、講義頁連結）怎麼利用？哪些嵌入模型能在 Ollama 離線跑（嵌入模型把文字轉成能比對相似度的數字）？中英混合怎麼檢索？怎麼降低編造？ | 高 |
| T3 | 複習的學習科學 | 什麼樣的複習最有效？包括測驗效應（考自己比重讀有效）、間隔重複（在快忘時複習）、出題與批改、用 Bloom 分級控制難度、回饋與提示怎麼給 | 高 |
| T4 | Agent 與 harness | 怎麼做成 agent？有三條路要比較：自己寫；用現成外殼（`ollama launch` 能接 Claude Code、Codex、OpenCode、Qwen Code、Hermes Agent、DeepSeek Harness 等）；用框架（例如 Qwen 官方的 Qwen-Agent）。另外要查：harness 由哪些元件組成、harness2 的改良方法能不能用本地模型跑 | 高 |
| T5 | 小模型做 agent | 7–9B 模型做 agent 有哪些已知問題和解法？包括工具呼叫穩不穩、結構化輸出、固定流程和自主規劃哪個好、驗證迴圈、針對工具呼叫的微調。現成外殼的系統提示很長、工具很多，對 9B 模型會不會太重？ | 高 |
| T6 | 個人化與訓練 | 怎麼記住使用者哪裡不會，也就是「學習者模型」？RAG 和微調各適合什麼？在 Mac 上用 LoRA 微調 9B 可不可行？互動紀錄能不能變成訓練資料？ | 中 |
| T7 | 介面 | 有哪些離線可用的介面：終端機、本機網頁（Gradio、Open WebUI 等）、Obsidian 外掛（課程筆記本來就在 Obsidian）、桌面 App？複習工具常見哪些互動設計，例如測驗模式、閃卡、錯題本？ | 中 |
| T8 | 評估 | 怎麼評估 AI 助教：答案正確率、出處是否真的支持答案、教學品質？用模型當評審有什麼限制？怎麼公平比較本地模型和 frontier 模型？ | 高 |

**不研究**：AI Cup 解法、期末專題分組。

### 每個主題的完成標準

- 表格裡的問題都有答案，或明確寫出「找不到可靠答案」。
- 至少精讀 3 份來源，其中至少 1 份 A 級。T4、T5、T7 變化快，A 級可能不夠；不夠時寫明缺口，不硬湊。
- 統整能直接支撐 `docs/` 裡的設計決定。

### 數量

篩選約 150 筆，精讀約 40 筆，其中 A 級至少 12 筆。

## 3. 來源分級

| 等級 | 什麼算 | 怎麼用 |
|---|---|---|
| **A 權威** | ① 同儕審查的期刊論文或會議正式論文，例如 ACL、EMNLP、NAACL、NeurIPS、ICLR、ICML、COLM；教育科技領域的 AIED、L@S、EDM、LAK、SIGCSE、ICER、BEA、EC-TEL；PNAS、Scientific Reports 與學習科學期刊。② 一手官方資料：工具或模型的官方文件、模型卡、官方 repo。官方資料只在「這個工具能做什麼」上算權威，不代表它的做法最好。③ 大學、政府或大型研究機構的正式報告 | 可以單獨當決策依據 |
| **B 參考** | ① arXiv 預印本，要有明確作者與機構，或附程式碼與可重現的評估。② workshop 論文、海報、2 頁延伸摘要：有審查但比正式論文輕。③ 大型 AI 實驗室的工程指南與技術報告。④ 持續維護的知名開源專案：近半年有更新、授權清楚、文件完整。⑤ 大學課程公開的實作與心得 | 可以參考；重要結論要有第二個來源或 A 級佐證 |
| **C 線索** | 個人部落格、Medium、論壇、影片、小型 repo、有信譽的媒體報導 | 只用來找方向，不單獨支撐任何決定 |

內容農場、匿名整理、轉貼、搜尋結果摘要一律不當證據，也不列入 C 級。

**確認刊登處**：可以用會議論文集頁面、ACL Anthology、PMLR、DOI 頁面或會議官網的論文頁。OpenReview 有瀏覽器驗證打不開時，改用會議官網，不要繞過。

### 和 media-note 查證規範的對應

media-note 的查證規範是為了查新聞和商業事實寫的，排序是：官方 > 同儕審查 > 第一方工程部落格 > 專業媒體。這裡研究的是「什麼方法有效」，所以有兩處調整：

- 官方資料和同儕審查論文都放在 A 級，但官方資料只對「工具能做什麼」權威。
- 專業媒體很少是方法的一手來源，降到 C 級。

不當證據的來源清單，兩邊一致。

### 附加規則

- **自家宣稱要標記**：關鍵數字只來自作者或廠商評測「自己做的工具或模型」、沒有獨立重現時，寫 `self_reported: true`，不當成已驗證的結果。例如模型卡、README 的跑分、自家系統的部署報告。有對照組的隨機實驗寫 `false`。
- **只讀摘要的來源**：統整裡要標「只讀摘要」。可以當佐證，但不能單獨支撐「已確認」。
- **本機實驗**：寫成筆記放在 `notes/internal/`，`type: doc`、`tier: internal`，寫明指令、輸入、輸出摘要和樣本數。
- **權威和適用分開評**：很多權威論文用的是 GPT-4 這類大模型，結論不一定適用於 9B 模型。每份筆記另外標適用度 `fit`（高／中／低）。
- **注意時效**：工具類資料記下版本與日期（Ollama 目前是 0.40.10）。超過一年的工具資料要確認是否過時。
- **等級可以升降**：預印本後來被會議接受就升 A 級；發現錯誤就降級並寫明原因。

### 主張的分類（沿用 media-note 查證規範）

`synthesis/` 裡每個重要主張都要標出一種狀態：

- **已確認**：至少兩個可靠且獨立的來源一致。同一個上游、同一家公司的兩頁只算一個。
- **單一來源**：只有一個來源，要寫明是誰說的。
- **互相矛盾**：兩邊都寫，並說明範圍或日期的差異。
- **查不到**：不寫成事實，標「待驗證」。

推論要標明是推論。必要來源拿不到、只找得到低品質來源、或來源矛盾又無法說清楚時，就停下來回報，不降低標準硬寫。

## 4. 搜尋管道

| 管道 | 找什麼 | 可信度看什麼 |
|---|---|---|
| Semantic Scholar、OpenAlex、arXiv、ACL Anthology、OpenReview、Google Scholar（透過網頁搜尋） | 論文 | 會議或期刊、引用數、作者機構。Semantic Scholar 和 DBLP 沒有金鑰時常回「請求太多」，可以改用 OpenAlex；不要為了提高額度填入使用者的 email |
| GitHub（`gh search`） | 開源專案 | 星數、最近更新、授權、有沒有對應論文、issue 活不活躍 |
| 官方文件：Ollama、Qwen、各 agent 外殼與框架 | 工具能做什麼 | 官方一手資料 |
| 一般網頁搜尋 | 大學導入案例、工程指南、技術文章 | 機構、作者、日期 |
| 本機小實驗 | 驗證文件的說法 | 自己測的，寫進筆記；需要安裝東西時先問使用者 |

## 5. 流程

1. **找起點**：每個主題先找 2–3 篇綜述或權威指南。
2. **往外擴**：往前看它們引用的論文，往後看後來引用它們的新論文。
3. **篩選**：每一筆先看標題和摘要（repo 看 README），決定留或刪，理由寫進 `search-log/T*.md`。「篩選數」就是寫進 search-log、做過留／刪判斷的候選數，刪掉的也算。
4. **精讀**：留下的寫成筆記（第 8 節）。開放取用的論文下載 PDF（第 6 節）。
5. **統整**：每個主題一份 `synthesis/T*.md`。
6. **合併**：主工作階段更新 `index.md`、寫 `synthesis/summary.md`，帶去跟使用者討論。

## 6. 論文 PDF

- 只下載開放取用的版本：arXiv、ACL Anthology、OpenReview、作者或機構官網。不繞過付費牆或登入。
- 存在 `pdfs/`，檔名和筆記相同（例如 `2024-cs50-ai.pdf`）。這個資料夾不進 Git。
- 筆記一定附原始連結，讓看 repo 的人能找到原文。

## 7. 平行研究的分工

| 工作階段 | 主題 | 可以寫的檔案 |
|---|---|---|
| 1 | T1、T7 | `search-log/` 與 `synthesis/` 的 T1、T7；新增筆記；`pdfs/` |
| 2 | T2、T6 | 同上，換成 T2、T6 |
| 3 | T3、T8 | 同上，換成 T3、T8 |
| 4 | T4、T5 | 同上，換成 T4、T5 |

- `index.md` 和 `synthesis/summary.md` 只由主工作階段在最後合併。
- 寫筆記前先在 `notes/` 搜尋同一個網址。已經有人寫過，就在原筆記的 `topics` 補上自己的主題，不另寫一份。
- 在別人寫的筆記補內容時，只能在末尾附加或局部編輯，不整份覆寫。
- 不修改別的主題的 search-log 和 synthesis。

## 8. 筆記

### 檔名

- 論文與網頁：`<年份>-<英文短名>.md`，例如 `2024-cs50-ai.md`。
- GitHub 專案：`<owner>-<repo>.md`，例如 `google-research-harness2.md`。

### 模板

```markdown
---
title: <標題>
type: paper            # paper / repo / doc / article / internal
tier: A                # A 權威 / B 參考 / C 線索；內部資料寫 internal
fit: 高                # 適用於 9B 本地離線：高 / 中 / 低
topics: [T2, T8]
year: 2025
venue: <會議或期刊；repo 寫星數、最後更新、授權>
url: <連結>
self_reported: false   # 數字是不是只有作者自己測
status: read           # screened 篩過 / read 精讀 / used 被決策採用
accessed: 2026-11-12
---
## 一句話
## 他們怎麼做（架構、模型、資料）
## 證據（怎麼評估、數字、樣本多大）
## 對 AI TA：可以借用／不適用（原因）
## 限制與疑點
```

`Machine Learning/` 是 Obsidian vault，屬性區可以直接篩選，例如篩出所有 A 級、適用度高的來源。

## 9. 產出格式

### `search-log/T*.md`

```markdown
## Semantic Scholar｜"LLM teaching assistant course"
- 結果 45 筆，看前 30 筆，留 6 筆
- 留：<來源>（理由）
- 刪：<來源>（理由）
```

### `synthesis/T*.md`

1. 這個主題的問題與結論摘要。
2. 別人怎麼做：分成幾種做法。
3. 比較表：做法、證據強度、適不適用於 9B 本地離線。
4. 對 AI TA 的建議，每條標明根據哪些來源、屬於哪種主張狀態。
5. 還不知道的事。

### `synthesis/summary.md`

跨主題的結論與建議架構，用來跟使用者討論。
