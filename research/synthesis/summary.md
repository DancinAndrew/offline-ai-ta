# 研究總結：離線課程複習 AI 助教

> 第 2 步，2026-11-11。8 個主題由 4 個平行工作階段研究，再由主工作階段合併。各主題的細節見 [T1](T1.md)–[T8](T8.md)，來源見 [index.md](../index.md)。這份是第 3 步討論用的材料，不是定案。

## 0. 規模與限制

- **篩選與精讀**：篩選約 270 筆（各工作階段計數方式不同，見各 search-log）。精讀並寫成筆記的外部來源 54 份：A 級 41、B 級 13。
- **內部資料**：另有 3 份——筆記格式、第 1 步的基準紀錄、本機工具呼叫實驗。
- **最大的限制**：多數 A 級研究用的是 GPT-4 等級的雲端模型。套到 9B 本地模型的地方，都標成推論，要靠自己的評估驗證。

## 1. 一句話結論

找不到「9B、完全離線、考試型複習」又有評估的前例（[T1](T1.md)，查不到）。但 8 個主題的證據指向同一個設計：

**由程式控制複習流程，每一步都把筆記原文放進提示當依據，讓 9B 只做單一、範圍窄的語言工作。**

## 2. 跨主題結論

| # | 結論 | 根據 | 狀態 |
|---|---|---|---|
| 1 | **講義知識用 RAG，不用微調灌進模型**。微調只在評估後、而且只用來調行為（引用格式、簡短、拒答） | RAG 在 7B 上全面勝過微調、硬學新知識會更常編造（Ovadia、Gekhman）；部署型助教都用 RAG（CS50、Jill Watson、Alan）。[T1](T1.md)、[T2](T2.md)、[T6](T6.md) | 已確認 |
| 2 | **每一步都附參考依據**：出題、批改、回饋、評審，都把筆記段落或參考答案放進提示 | 附老師解法的 AI 家教不傷學習或勝過課堂（Bastani、Kestin）；評審附參考答案後，數學題失敗率從 70% 降到 15%（Zheng）。[T1](T1.md)、[T3](T3.md)、[T8](T8.md) | 已確認（大模型）；對 9B 一樣有效是推論 |
| 3 | **程式控制流程，9B 每一步只做一個單輪決定**，不讓它自主規劃整段複習 | 小模型單輪工具呼叫接近頂尖、多輪明顯落後（BFCL、α-UMi、ReAct）；Kestin 發現光靠系統提示撐不起多步驟題，要用固定步驟。[T3](T3.md)、[T4](T4.md)、[T5](T5.md) | 小模型多輪弱：已確認；在 AI TA 上固定流程勝過自主 agent：推論（沒有直接對照研究） |
| 4 | **複習「先考、再講」；練習時不直接給答案** | 練習測驗和分散複習證據最強；高資訊回饋 d = 0.99，只說對錯 d = 0.24；練習時 AI 直接給答案，拿掉 AI 後考試退步 17%（Bastani）。[T3](T3.md) | 效果方向：已確認；給答案的傷害：單一來源；問概念時可以直接解釋：推論 |
| 5 | **速度是硬限制**：只檢索少數段落、回答要短、系統提示的開頭保持不變（才能用快取） | 本機量到讀提示約每秒 200–250 token、生成約每秒 10 token；期中筆記約 44 萬 token，放不進模型；Codex 的基本指示 4,589 token，冷啟動要 17 秒。[T2](T2.md)、[T4](T4.md)、[T5](T5.md) | 已確認（官方文件＋本機量測） |
| 6 | **9B 的失敗要靠程式擋，不能只靠提示詞** | 本機實驗：預設溫度下 23 次有 3 次「沒呼叫工具，卻說已記錄」；沒有外部依據的自我修正會把對的改錯（ICLR 2024）。[T5](T5.md) | 失敗確實存在：已確認；發生頻率：查不到 |
| 7 | **離線要主動關掉、還要驗收**：預設會連網的地方不少 | Ollama 的雲端模型和 web search 預設開著（這台機器也是）；Gradio 的使用分析預設開；Open WebUI 的 `OFFLINE_MODE` 不會擋住對外連線。[T7](T7.md) | 已確認（官方文件＋本機 log） |
| 8 | **評估以使用者盲評為準；16 題主要用來找失敗類型，不能宣稱顯著** | 8B 評審評教學品質，和人類判斷多為負相關（MRBench）；16 題配對比較時，表現不同的 6 題要全部同一邊贏才達到 p < 0.05。[T8](T8.md) | 小模型評審不可靠：已確認；小樣本檢定力不足：已確認；建議的統計方法：單一來源 |

結論 8 會影響核心假設的說法：只靠 16 題，沒辦法「證明」AI TA 接近 frontier，只能呈現逐題比較和失敗類型。要說得更多，就得擴充題組（見第 4 節第 4 條）。

## 3. 建議架構（草案）

```text
介面：終端機（開發、跑評估）／本機網頁 Gradio（複習用，能排版公式）／Obsidian 外掛（核心穩定後）
                       │
Python 核心：程式控制流程；harness 拆成 8 個元件，各存一個純文字檔
 ├─ 檢索：直接讀 vault 的 .md 原檔 → 依最小標題節切段 → 向量＋關鍵字混合檢索 → 取 3–5 段、附編號
 ├─ 三種模式
 │   ├─ 搜尋模式：只列出相關的筆記段落，不經過模型生成
 │   ├─ 解釋模式：短答，逐句標出處 [n]；筆記裡沒有就直接說沒有
 │   └─ 練習模式：出題（回想題為主）→ 使用者作答 → 對照參考答案批改 → 高資訊回饋 → 排下次複習
 ├─ 學習者模型：只新增的作答紀錄 → 重算每個知識點的掌握度 → FSRS 排程（存在 data/learner/）
 └─ 評估：題組、程式量測（長度、延遲、出處連結是否有效）、評分表
                       │
Ollama：qwen3.5:9b ＋ 一個嵌入模型；設定 OLLAMA_NO_CLOUD=1
```

**主要的預設選擇**

- **知識點的 ID**：就用筆記的標題節。檢索、學習者模型、出處共用同一套 ID，所以「哪裡不會」可以直接連回要複習的筆記和講義頁（[T2](T2.md)、[T6](T6.md)）。
- **索引**：期中範圍約 965 節。用 SQLite 存，FTS5 做關鍵字檢索，向量逐一算相似度就夠了，不需要向量資料庫（[T2](T2.md)，推論）。
- **嵌入模型**：先比 `bge-m3`、`qwen3-embedding:0.6b`、`embeddinggemma-2:270m`，用自己的題組量「前 5 名有沒有找到對的節」（[T2](T2.md)）。
- **出處格式**：逐句標 `[n]`，介面再轉成「Week6 筆記 > 小節名稱＋講義 p.xx」，並能點開講義那一頁。本機 3 題小測可行，回答 76–229 字（[T2](T2.md)）。
- **工具呼叫與結構化輸出**：調低溫度；用 `format` 指定 schema，再用 Pydantic 驗證；需要推理的欄位放前面。只有工具真的執行成功，才由程式告訴使用者結果（[T5](T5.md)）。
- **思考模式**：只在需要推理的步驟打開（[T5](T5.md)）。
- **現成外殼**：Codex、Qwen Code 等只當評估時的對照組，不當主體（[T4](T4.md)）。
- **微調**：評估後才決定要不要做，而且只調行為（[T6](T6.md)）。

## 4. 需要你決定的事

1. **frontier 模型的使用界線。**
   - 計畫目前只寫「評估時使用」。研究提出兩個新用途：開發期提出 harness 的改良建議（[T4](T4.md)），以及產生微調的訓練資料（[T6](T6.md)）。
   - 我的建議：執行時一律離線；開發與評估可以用 frontier 模型，但每次使用都記錄下來，對外報告寫清楚哪些改良來自 frontier 的建議。
   - 補充：我（Claude）本身就是 frontier 模型，目前的研究和開發已經在用了。
2. **frontier 對照組要給什麼資料。**
   - 「同樣檢索到的段落」可以隔離模型能力的差異；「完整筆記」是上限參考（[T8](T8.md)）。
   - 我的建議：兩種都做。
3. **「接近 frontier」的門檻。**
   - 研究沒有現成標準，要寫進 `docs/requirements.md`。例如：「16 題中有幾題和 frontier 一樣好或更好，而且回答長度、延遲在某個範圍內」。
   - 這要你給一個能接受的標準。
4. **評估題組怎麼擴充。**
   - 16 題的參考答案：我從筆記起草，你核對。
   - 加「陷阱題」：故意把正確的理解改錯一處，看 AI TA 會不會順著使用者說對。
   - 從筆記的「自我檢查」和 `Midterm Review/` 補題。從講義或練習題摘錄的題目，放在不公開的檔案。

到第 5 步開發時，還要安裝幾樣東西：嵌入模型（`ollama pull`，每個小於 1.3 GB）、Gradio（`uv add`）。到時再逐項問你。

## 5. 還不知道、要自己量的事

- **繁中與中英混合的檢索效果**：沒有繁體中文的檢索基準，要用題組自己量。
- **依標題切段和固定長度切段**，在這批筆記上哪個好。
- **qwen3.5:9b 的實際表現**：
  - 出題時，Bloom 層級符合率多少（7B 等級的研究約 60%）；
  - 批改開放式回答的準度；
  - 多輪對話的可靠度。
- **固定流程 vs 自主 agent**：同一個 9B 模型在複習任務上差多少，沒有研究，可以在第 7 步當額外對照。
- **本機設定的疑點**：
  - API 傳 `num_ctx: 65536` 之後，`ollama ps` 仍顯示 32768。
  - 生成速度約每秒 10 token，比第 1 步推算的慢，原因不明。
  - Ollama App 聊天時會不會在提示裡放搜尋工具的說明。
- **各工具斷網後的實際行為**：Gradio、Open WebUI 和各外殼都沒有安裝實測。
- **投影片 PDF 的離線解析**沒有研究。先只索引筆記，因為筆記已經有講義頁連結；筆記沒涵蓋的投影片內容會漏掉。
- **學習科學的效果大小**多來自事實記憶、立即測驗；用在研究所概念題時效果多大，查不到。
- **單人、少量資料的知識追蹤**沒有文獻。

## 6. 第 5 步建議的順序（草案）

1. **離線設定與斷網驗收**：關掉 Ollama 的雲端功能，在斷網狀態下跑一次。
2. **補題組**：16 題的參考答案，加上陷阱題。
3. **切段與索引**：比較 3 個嵌入模型、兩種切段方式的檢索命中率。
4. **解釋模式**：附出處的問答跑完 16 題，和基準線比較正確性、長度、延遲。
5. **練習模式**：出題、批改、回饋。
6. **學習者模型與複習排程。**
