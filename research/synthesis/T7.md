# T7 介面：離線可用、適合複習

> 2026-11-11，T1／T7 工作階段。來源清單與篩選理由見 [search-log/T7.md](../search-log/T7.md)。主張狀態依 [README](../README.md) 第 3 節；依 media-note 查證規範，官方原始文件可以在它負責的範圍內單獨確認一件事，這種情況標「已確認（官方文件）」。推論另外標明。

## 1. 問題與結論摘要

**問題**：有哪些離線可用的介面：終端機、本機網頁、Obsidian 外掛、桌面 App？複習工具常見哪些互動設計，例如測驗模式、閃卡、錯題本？另外要查：執行時會不會偷偷需要網路；能不能直接讀 Obsidian 筆記的原始 Markdown。

**結論**：

1. **讀筆記：直接讀 vault 資料夾裡的 `.md` 原檔就好**。Obsidian 的 vault 就是一個資料夾，外掛透過 Vault API 讀到的也是原始文字；原檔裡的公式是 LaTeX 原文，不會像從閱讀畫面複製那樣消失。（已確認：Obsidian 官方文件 + 本機檢查）
2. **機器學習筆記幾乎都有公式，所以介面一定要能排版公式**。本機檢查：Week2–8 與 Midterm Review 的 61 個筆記檔中，55 個含 `$`。終端機用 Rich 顯示時只會印出 LaTeX 原始碼。（筆記含公式：本機檢查；Rich 不排版：由原始碼推論）
3. **「偷偷需要網路」的地方，每個工具都有，而且多半預設開著**：
   - Ollama 的雲端模型和 web search 預設開著；這台機器目前也是開著的。（已確認：官方文件 + 本機 log）
   - Gradio 的使用分析預設開著。（已確認（官方文件））
   - Open WebUI 第一次要從網路下載嵌入模型；`OFFLINE_MODE` 只關掉更新檢查和模型下載，不會擋住其他對外連線。（已確認（官方文件））
   - 對照組：新版 Gradio 的預設字型是內建檔案，公式用打包的 KaTeX，看起來不需要 CDN。（由原始碼推論，未實測）
4. **現成的整合介面都不完全合用**：Open WebUI 很重，內建檢索不認得 media-note 的結構；Copilot for Obsidian 的提示與流程由外掛決定；Smart Connections 要接 Ollama 對話得付費；閃卡外掛會把排程寫回課程筆記。（各自為單一來源；「不合用」是推論）
5. **複習工具的互動設計有成熟範本，但成效證據少**：
   - 範本：Anki 的「先想、再翻答案、自評、排程」與 leech（反覆忘記的卡）；NotebookLM 的閃卡、測驗、按「explain」看解說；Alan 的可點出處與搜尋模式；Ruffle&Riley 的「原文在旁、求助按鈕」。
   - 成效：對話式家教沒有比單純閱讀學得多（Ruffle&Riley，單一來源）；錯題本的實驗研究查不到。

## 2. 別人怎麼做

### 四類介面

- **終端機**：`ollama run` 或自己寫的 Python 程式（Rich 排版 Markdown）。不需要任何前端資源；但公式只能顯示原始碼。
- **本機網頁**：
  - **Gradio**（[2026-gradio-offline](../notes/web/2026-gradio-offline.md)）：Python 幾十行就能做聊天加表單；新版字型與公式渲染都打包在套件裡（推論）；使用分析要手動關。
  - **Open WebUI**（[2026-open-webui-offline](../notes/web/2026-open-webui-offline.md)）：功能最完整的聊天介面，內建知識庫檢索；離線要事先快取模型、另外用防火牆隔離；單人可以關掉登入。
  - **Streamlit**：只看到搜尋摘要，使用統計預設開啟（待驗證）。
- **Obsidian**（[2026-obsidian-cli-vault-api](../notes/web/2026-obsidian-cli-vault-api.md)）：
  - 自己寫外掛，用 Vault API 讀原始 Markdown。
  - 官方 CLI（1.12.7 起）可以 `read`、`search`，但要 App 在執行。
  - 現成外掛：Copilot for Obsidian（[筆記](../notes/repos/logancyang-obsidian-copilot.md)）可接本機模型，但已變成 agent 平台；Smart Connections（[筆記](../notes/repos/brianpetro-obsidian-smart-connections.md)）只做相關筆記推薦；Local GPT 偏寫作輔助。
- **桌面 App**：Ollama App（[2026-ollama-cloud-offline](../notes/web/2026-ollama-cloud-offline.md)；基準紀錄就是用它）、Jan、AnythingLLM、LM Studio。後三者這次只篩選，官方隱私文件沒讀。

### 複習互動設計

| 設計 | 誰這樣做 | 怎麼運作 |

## 4. 對 AI TA 的建議

1. **資料層直接讀 vault 的 `.md` 原檔**，不靠複製貼上，也不依賴 Obsidian 在執行。
   - 根據：Obsidian 官方文件（vault 是資料夾、Vault API 回傳原始內容）；本機檢查與基準紀錄（原檔公式完整、從閱讀畫面複製會遺失）。已確認（官方文件 + 本機檢查）。
   - 要自己解析 `[[...pdf#page=25|...]]` 這種講義連結（交給 T2）。
2. **介面分兩層：一個 Python 核心，外面套薄的外殼。**
   - 開發與評估先用終端機：可重現、可以自動跑評估題組。
   - 給人用的複習介面用本機網頁（Gradio 優先），因為要排版公式。
   - Obsidian 外掛等核心穩定後再考慮。
   - 根據：CS50「一個後端、多個入口」的做法（見 [T1](T1.md)）；筆記多含公式（本機檢查）；Gradio 的公式與字型在本機（推論，未實測）。整體是推論。
3. **把「完全離線」寫成驗收清單**，第 5 步「斷網能跑」照表檢查：
   - Ollama 設 `OLLAMA_NO_CLOUD=1`（或 `server.json`），只允許本機模型名稱。（依據已確認：官方文件 + 本機 log）
   - Gradio 設 `GRADIO_ANALYTICS_ENABLED=False`、不開 share、主題只用內建字型。（依據已確認（官方文件））
   - 嵌入模型事先下載到本機。（依據：Open WebUI 文件的同類陷阱；推論適用於 AI TA）
   - 斷網後跑一輪：一般問答、附出處的問答、出題、批改；再用網路監看確認沒有對外連線。（參考 Open WebUI 的驗收步驟；清單本身是推論）
4. **測驗模式採 Anki 式流程**：出題 → 使用者先作答 → 顯示參考答案與講義頁出處 → 判對錯 → 排下次複習。
   - AI 批改只給「錯／對」兩級，對應 Again／Good，避免把「錯」記成 Hard 而讓排程過度樂觀。（根據 Anki 官方手冊對 Hard 的警告，單一來源；兩級設計是推論）
   - 「先作答」也呼應 PNAS 的結論（見 [T1](T1.md)）。
5. **錯題本 = 同一概念錯到門檻就收進來，處理方式是換方式重新解釋，而不是同一題一直考。**
   - 根據：Anki 的 leech 設計與手冊建議（單一來源，官方對自己工具的說明）。錯題本本身的成效研究查不到，所以這是推論。
6. **提供快速模式**：「搜尋模式」（只列出筆記段落，不生成）和「快速測驗」；對話式追問當選配。
   - 根據：Alan 有搜尋模式（單一來源）；Ruffle&Riley 的對話式家教花 3–4 倍時間卻沒有學得更多（單一來源）；基準紀錄平均 74 秒。推論。
7. **不拿現成整合介面（Open WebUI、Copilot for Obsidian）當主介面**，只當對照或備案。
   - 理由：提示與流程不可控，無法精確控制送給 9B 的系統提示和工具數量（T5 的疑慮）；內建檢索不懂 media-note 結構；評估不能重現。推論。
8. **閃卡可以從筆記自動產生，但排程不要寫回課程筆記。**
   - media-note 每節的 `==螢光==` 結論可以變成挖空卡，加上「筆記 > H2 > H3」當脈絡（推論）。
   - Obsidian Spaced Repetition 會在每張卡後面加 `<!--SR:...-->` 註解（單一來源，該外掛文件）；AI TA 的學習紀錄應該放在 `data/learner/`，不動課程筆記（推論，符合 plan 的「講義不複製、不修改」原則）。

## 5. 還不知道的事

- **實際斷網的行為**：Gradio、Open WebUI 依規定沒有安裝，都只讀了文件與原始碼；Ollama App 斷網時是否仍嘗試連線，也沒測。開發階段第一件事就是斷網實測。
- **Ollama App 聊天時會不會在提示裡放搜尋工具說明**：文件沒寫（待驗證；和基準紀錄的疑點有關）。
- **桌面 App 的遙測**：Jan、AnythingLLM、LM Studio 的官方隱私文件沒讀；第三方說法互相矛盾。
- **Obsidian 的細節**：CLI `read` 會不會輸出屬性區；Obsidian 原生公式渲染的官方說明沒讀。
- **Open WebUI 與 Textual 的公式渲染**：查不到。
- **互動設計的成效**：錯題本、測驗介面、閃卡介面的實驗研究查不到；AI 產生閃卡的研究只有 6 人的形成性研究（SmartFlash）和未審查的設計論文（Memdora）。
- **排程目標**：這門課期中後沒有期末考，複習是為了長期記住還是某一天的考試，會影響 FSRS 的期望記憶率怎麼設（交給 T3）。
