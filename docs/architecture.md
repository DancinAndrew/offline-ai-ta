# 架構

> 2026-11-11 定案（決策紀錄 [0004](decisions/0004-architecture.md)）。開發中要改架構，先新增決策紀錄。需求見 [requirements.md](requirements.md)，每個選擇的研究依據見 [research/synthesis/summary.md](../research/synthesis/summary.md)。

## 1. 原則

1. **程式控制流程**：步驟由程式決定，9B 每一步只做一個單輪的語言工作。
2. **每一步都有依據**：提示裡一定附上筆記原文或參考答案，不讓 9B 憑記憶回答或批改。
3. **能由程式做的就不交給模型**：檢索、記錄、排程、格式驗證、出處檢查都由程式做。
4. **短而快**：只檢索 3–5 段、回答要短；系統提示的開頭保持不變，讓 Ollama 能重複使用快取。
5. **離線是預設**：會連網的功能一律關掉，並且要驗收。

## 3. 資料

| 資料 | 位置 | 說明 |
|---|---|---|
| 課程筆記 | `Machine Learning/Week*/`、`Midterm Review/` | 唯讀，不複製、不修改 |
| 知識清單 | `data/knowledge/` | 要索引哪些檔案；公開 |
| 索引 | `data/index/` | SQLite：段落、向量、FTS5 關鍵字索引；可以重建；只在本機 |
| 學習者資料 | `data/learner/` | 只新增的作答紀錄＋可重算的衍生狀態；只在本機 |
| 評估 | `dev/eval/` | 題組與每次的結果；`private/` 只在本機 |

**知識點 ID**：用筆記的標題節，例如「Week6 > 決策樹 > 資訊增益偏好值很多的特徵，C4.5 和 CART 怎麼修正？」。檢索、出處、學習者模型都用同一套 ID，所以「哪裡不會」能直接連回要複習的筆記和講義頁。

## 4. 流程

### 4.1 建索引

1. 依 `data/knowledge/` 的清單讀筆記原檔。
2. 依最小的標題節切段（H2、H3 或 H4），保留 Markdown 原文和 LaTeX。
3. 每段前面接上「檔名 > H2 > H3」，並記下段內的講義頁連結。
4. 用嵌入模型算向量，依段落文字的雜湊值快取，沒改到的段落重建時不必重算；另用 SQLite FTS5 建關鍵字索引（中文拆成相鄰兩字一組）。
5. 期中範圍約 965 節，逐一算相似度就夠了，不需要向量資料庫。

### 4.2 搜尋模式

問題 → 向量檢索 → 列出前幾段的標題路徑和講義頁連結。不呼叫生成模型。關鍵字和混合檢索可以用選項切換（[0005](decisions/0005-retrieval.md)）。

### 4.3 解釋模式

1. 程式先檢索出 3–5 段，編號 `[1]`–`[5]`。模型不需要呼叫工具。
2. 提示依序放入：固定的系統提示、護欄、編號段落、問題。
3. qwen3.5:9b 回答（預設關閉思考模式），逐句標 `[n]`；筆記裡沒有就說沒有。
4. 程式檢查：每個 `[n]` 都在範圍內、對應的段落存在。檢查不通過就重試一次，或標示「出處不足」。
5. 介面把 `[n]` 轉成「Week6 筆記 > 小節名稱＋講義 p.xx」，可以點開。

**確認理解題**：提示要求先逐句判斷使用者的說法對不對，再補充。

### 4.4 練習模式

1. **選知識點**：依學習者模型，選到期要複習的、常錯的，或使用者指定的。
2. **取依據**：檢索該節原文，以及「這節記住」和「自我檢查」的答案，當參考答案。
3. **出題**：結構化輸出，內容包括題目、Bloom 層級、參考要點。程式驗證格式；不符合就重出。
4. **作答**：作答前只給提示，提示要指出具體的下一步。
5. **批改**：結構化輸出，包括 5 類標籤、哪些對、哪些錯、回饋、出處。對照參考答案，不靠模型記憶。
6. **記錄與排程**：程式寫入作答紀錄，重算掌握度，用 FSRS 排下次複習。批改結果只分兩級，對應 FSRS 的 Again／Good。
7. **錯題本**：同一個知識點錯到門檻，就改用另一種方式重新解釋，而不是同一題一直考。

## 5. harness 的檔案

沿用 harness2 的 8 個元件，每個元件一個純文字檔，放在 `dev/harness/`：

| 元件 | 檔案 | AI TA 的內容 |
|---|---|---|
| 系統提示 | `systemprompt.md` | 助教的角色、回答長度、引用格式 |
| 護欄 | `guardrails.md` | 只根據段落回答、查不到要說、練習時不直接給答案 |
| 記憶 | （程式產生） | 學習者狀態摘要，例如「Gini 相關題目錯過 3 次」 |
| 技能 | `skills/explain/`、`skills/quiz/`、`skills/grade/` | 各模式的步驟說明與範例 |
| 工具說明 | `tool_guidance.md` | 最小化：多數步驟由程式先做好，模型不呼叫工具 |
| 腳本 | `dev/src/ai_ta/` 的驗證函式 | JSON 驗證、出處檢查、排程 |
| 子代理 | 不使用 | — |
| 外掛（中介層） | `llm` 模組 | 驗證失敗就重試、記錄每次呼叫、只有工具真的成功才回報結果 |

每次評估都記錄 harness 的 Git commit。改良時一次只改一個元件，用同一組題目重跑，比較後有證據才保留。

## 6. 技術選擇

| 項目 | 選擇 | 狀態 |
|---|---|---|
| 語言 | Python 3.12（上層共用的 uv 環境） | 已有 |
| 生成模型 | qwen3.5:9b（[0001](decisions/0001-base-model-qwen3.5-9b.md)） | 已有 |
| 呼叫方式 | Ollama HTTP API：`/api/chat`（`format`、`think`）、`/api/embed` | 已有 |
| 嵌入模型 | `qwen3-embedding:0.6b`，比較 3 個候選後選定（[0005](decisions/0005-retrieval.md)） | 已下載 |
| 索引 | SQLite 與 FTS5（Python 內建） | 已有 |
| 結構化輸出驗證 | Pydantic | 已安裝（2.14.3） |
| 排程 | py-fsrs | 已安裝（fsrs 6.3.2） |
| 終端機介面 | Rich | 共用環境原本就有 |
| 網頁介面 | Gradio | 第 6 步安裝，先問 |

**取樣設定**：結構化輸出和工具步驟調低溫度；思考模式只在需要推理的步驟開。

## 7. 離線驗收清單

- [ ] Ollama 設 `OLLAMA_NO_CLOUD=1`（或 `server.json`），只允許本機模型。
- [ ] 嵌入模型事先下載到本機。
- [ ] Gradio 設 `GRADIO_ANALYTICS_ENABLED=False`，不開 share，只用內建字型。
- [ ] 斷網後完整跑一輪：搜尋、解釋（附出處）、出題、批改。
- [ ] 跑的同時監看網路，確認沒有對外連線。

## 8. 延後或不做

| 項目 | 什麼時候再考慮 |
|---|---|
| 微調 | 評估後，提示詞加 RAG 在格式、拒答或長度上的失敗率仍然太高；只調行為 |
| 現成 agent 外殼 | 第 7 步當對照組 |
| 自主 agent 規劃 | 第 7 步當對照組 |
| 重排序、改寫查詢 | 檢索命中率不夠時 |
| 混合關鍵字檢索 | 題組擴充到約 50 題後重測（[0005](decisions/0005-retrieval.md)） |
| 投影片 PDF 解析 | 筆記沒涵蓋的內容成為問題時 |
| Obsidian 外掛 | 核心穩定後 |

## 9. 開發時要先查清楚的事

- API 傳 `num_ctx: 65536` 後，`ollama ps` 仍顯示 32768。
- 生成速度約每秒 10 token，比第 1 步推算的慢。
- 中文關鍵字檢索：改用相鄰兩字一組的分詞，兩個字的術語可以比對了，但口語問題的命中率仍低（[0005](decisions/0005-retrieval.md)）。
- 依標題切段和固定長度切段，哪個好。
- 思考模式在每個步驟的成本和效果。
