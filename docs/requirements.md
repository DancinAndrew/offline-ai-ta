# 需求與成功標準

> 2026-11-11 定稿，依據第 2 步研究（[summary](../research/synthesis/summary.md)）與決策紀錄 [0002](decisions/0002-frontier-model-boundary.md)–[0004](decisions/0004-architecture.md)。目標與範圍見 [plan.md](plan.md)，架構見 [architecture.md](architecture.md)。

## 1. 使用者與情境

- **使用者**：只有我一個人。
- **情境**：離線複習機器學習課，例如在飛機上。素材是期中考範圍（Week 1–8）的課程筆記與期中複習資料。這門課沒有期末考。
- **語言**：繁體中文，保留英文術語。筆記裡有大量 LaTeX 公式（61 個筆記檔中有 55 個含公式）。

## 2. 功能需求

| # | 需求 | 說明 |
|---|---|---|
| F1 | 讀取課程筆記 | 直接讀 vault 的 `.md` 原檔，保留 LaTeX 公式和講義頁連結；**不修改課程筆記** |
| F2 | 搜尋模式 | 輸入問題，列出相關的筆記段落和講義頁，不經過模型生成 |
| F3 | 解釋模式 | 短答；逐句標出處，出處能點回筆記段落和講義頁；筆記裡沒有就直接說沒有 |
| F4 | 練習模式 | 依知識點出題（回想題為主，指定 Bloom 層級）→ 我作答 → 對照參考答案批改（5 類）→ 高資訊回饋（錯在哪、為什麼、正確推理、出處）。作答前只給提示，不直接給答案；我明確放棄時才給 |
| F5 | 確認理解 | 我說出自己的理解時，先逐句指出哪裡對、哪裡錯，再補充；不順著我說 |
| F6 | 學習者模型與排程 | 記錄每次作答；算出每個知識點的掌握度；用 FSRS 排下次複習；列出常錯的知識點（錯題本），處理方式是換個方式重新解釋 |
| F7 | 評估工具 | 跑題組、量長度和延遲、檢查出處連結、匯出盲評表（見 [0003](decisions/0003-evaluation-design.md)） |

## 3. 非功能需求

| # | 需求 | 標準 |
|---|---|---|
| N1 | 離線 | 執行時完全不需要網路，通過離線驗收清單（[architecture.md](architecture.md) 第 7 節） |
| N2 | 速度 | 解釋模式每題回答時間的中位數 ≤ 40 秒（模型已載入時量） |
| N3 | 長度 | 解釋模式回答長度的中位數 ≤ 600 字 |
| N4 | 本機資源 | 在 Apple M5、32 GB 上，生成模型和嵌入模型同時運作 |
| N5 | 隱私與著作權 | `records/`、`data/learner/`、`data/index/`、`research/pdfs/`、`dev/eval/private/` 不進公開 repo |
| N6 | 可重現 | 評估可以重跑；記下模型、設定、harness 版本（Git commit）和隨機種子 |

## 4. 成功標準

詳見 [0003](decisions/0003-evaluation-design.md)。以下標準在看到任何 AI TA 結果之前訂定，要修改必須新增決策紀錄。

**前提**（沒達成就不算達標）：

- 通過離線驗收（N1）。
- 出處標記 100% 對應到真實存在的段落和講義頁。

**接近 frontier**（三項都要達到）：

1. 在我盲評的逐題配對比較中，至少 75% 的題目 AI TA 和 frontier A（同樣檢索段落）一樣好或更好。
2. 解釋模式回答時間中位數 ≤ 40 秒（N2）。
3. 解釋模式回答長度中位數 ≤ 600 字（N3）。

**一併報告**：Wilson 區間；和 frontier B、基準線的比較；逐題的失敗類型。不宣稱統計顯著。

## 5. 不在範圍內

- 寫作業、Lab、AI Cup 用的程式輔助（AI TA 完成後才拿去協助 AI Cup）。
- 多人使用、登入、雲端同步。
- 用微調把講義知識灌進模型。
- 期末專題的分組功能。
