# 0004 架構：由程式控制流程的薄 harness

- 日期：2026-11-11
- 狀態：提議中，等我確認 [architecture.md](../architecture.md)

## 背景

第 2 步研究的跨主題結論見 [research/synthesis/summary.md](../../research/synthesis/summary.md)。和架構直接相關的有四點：

- 找不到「9B、完全離線、考試型複習」的前例。
- 小模型多輪自主決策弱，單輪接近頂尖。
- 每一步附參考依據能讓 AI 家教和評審更可靠。
- 本機速度是硬限制。

## 決定

1. **自己寫 harness**：寫一個由程式控制流程的薄 harness，直接呼叫 Ollama 的 API。現成的 agent 外殼（Codex、Qwen Code 等）不當主體，只當評估時的對照組。
2. **講義知識用 RAG**：
   - 直接讀 vault 的 `.md` 原檔；
   - 依最小的標題節切段；
   - 用向量加關鍵字的混合檢索。
3. **三種模式**：搜尋、解釋、練習。練習模式「先考、再講」，作答前不直接給答案。
4. **每一步都有依據，而且只做一件事**：
   - 每一步都把筆記原文或參考答案放進提示。
   - 9B 每一步只做一個單輪的工作。
   - 能由程式做的事（檢索、記錄、排程、驗證）不交給模型。
5. **學習者模型**：只新增的作答紀錄，加上可以重算的掌握度和 FSRS 排程。
6. **介面分層**：
   - 一個 Python 核心；
   - 終端機，用在開發和評估；
   - 本機網頁（Gradio），用在複習；
   - Obsidian 外掛等核心穩定後再考慮。
7. **不用微調灌知識**：不用微調把講義知識灌進模型。要不要微調，等評估後才決定，而且只調行為。

## 理由

| 決定 | 主要根據 |
|---|---|
| 1、4 | 小模型多輪弱（BFCL、α-UMi）；複習流程本身是固定步驟；現成外殼的系統提示長、官方建議 64k 上下文（[T4](../../research/synthesis/T4.md)、[T5](../../research/synthesis/T5.md)） |
| 2、7 | RAG 勝過微調灌知識（Ovadia、Gekhman）；直接讀原檔才能保留公式（[T2](../../research/synthesis/T2.md)、[T6](../../research/synthesis/T6.md)、[T7](../../research/synthesis/T7.md)） |
| 3 | 先考再講、高資訊回饋、練習時不給答案（[T3](../../research/synthesis/T3.md)） |
| 5 | 單人資料少，用簡單、可解釋的方法；換算法時重算就好（[T6](../../research/synthesis/T6.md)） |
| 6 | 筆記多含公式，終端機排版不了；開發和評估需要能重現（[T7](../../research/synthesis/T7.md)） |

## 後果

- **要自己寫的東西比較多**，但每個環節都可以單獨替換和評估。
- **有一點還沒有直接證據**：在這個情境裡，「固定流程勝過自主 agent」沒有直接研究支持。第 7 步可以加一組「qwen3.5:9b ＋ 現成外殼」或自主 agent 當對照，實際驗證。
